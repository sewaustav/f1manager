# Ревью паритета CLI ↔ Web

Дата: 2026-07-29. Только анализ несоответствий, код не менялся.
Сравниваются игровая логика CLI (`internal/cli/`) и веб-сервис (`internal/service/`) поверх общего движка (`internal/engine/`).

## Общий движок — паритет есть

`SimulateWeekend` (квалификация, гонка, DNF, очки, `updateAfterRace`) и `UpdateAfterSeason` — один код для обеих версий. Симуляция уик-энда, дефолты ботов (`Car{20,...}`, `TeamPrincipal{Level:20}`) идентичны в `cli/sim.go` и `service/service.go`.

## Несоответствия (по убыванию важности)

### 1. Межсезонье не оркестрируется в вебе — КРИТИЧНО
- CLI: `runSimulation` → `UpdateAfterSeason` → `resetTokensAndBudget` → `crossSeason` (цикл: трансферы → `start` → `buildCarForNextSeason` → `fillBotTeams` → `configureSeason` → новый сезон).
- Web: `Simulate` — только одна гонка (вызывается диспетчером). **`UpdateAfterSeason` в вебе не вызывается нигде** (только `cli/sim.go:318`). Нет перехода «финальная гонка → пересчёт рейтингов → сброс → новый сезон». Рейтинги пилотов по итогам сезона в вебе не обновляются.

### 2. Начисление токенов 120 + 10×(место−1) не реализовано
- CLI: `resetTokensAndBudget` (`cli/cross_season.go:89`) — `tokens := 120 + 10*(rank[team]-1)`.
- Web: `ResetSeason` → `dynamic.ResetTokensAndBudget`. Redis-реализация (`redis/dynamic.go`) ставит **плоские `Tokens = 120`**, без ранга по Кубку конструкторов. Плюс требование ТЗ «токены раздаются перед каждой гонкой» — в вебе **нет** пред-гоночной раздачи (в `Simulate` токены не переустанавливаются).

### 3. Пересчёт бюджета на стыке сезонов отсутствует
- CLI `resetTokensAndBudget` пересчитывает бюджет из стоимости пилотов (`price - sponsors`) + принципала + мотора и корректирует.
- Web `ResetTokensAndBudget` (Redis) бюджет **не трогает** — только токены.

### 4. Таблицы `calcBonus` разошлись
- CLI `calcBonus` (`cli/cross_season.go:360`) и web `calcBonus` (`service/engine.go:96`) имеют **разные весовые матрицы** и разное поведение на неизвестном ключе (CLI → `input`, web → `0`). Web добавляет обёртку `getBonus` (для `price==0` даёт отрицательный бонус) — в CLI её нет. Итоговые распределения улучшений отличаются между версиями.

### 5. Инвестиции в базу: разные функции и кэпы
- CLI `buildCarForNextSeason` применяет `calcBonus(x)` напрямую, `CarLevel` = среднее 5 компонентов; проверка лимитов до применения.
- Web `UpdateBase` (`service/service.go:235`) использует `getBonus(x, max)` и пост-кэпы `min(..., 5)` для engineer/tube/sim и `min(..., 100)` для base. Числа расходятся с CLI.

### 6. Окна обновлений болида: тайминг не форсится
- CLI: сбор апдейтов на этапах 3/8/13, применение на 7/12/18 (эффект через 4 гонки) — жёстко в коде (`cli/sim.go`).
- Web: применение на 7/12/18 в `bringUpdate` совпадает, но **сбор** зависит от `req.Stage`, который присылает клиент (`MakeUpdate`), — сервер не проверяет, что апдейт подан именно на 3/8/13.

### 7. Не реализованы cross-season операции CLI
В вебе отсутствуют сервис-методы и хендлеры для команд, которые есть в CLI (`cli/cross_season.go`):
- **Обмен пилотами между игроками** (`change` — своп с денежной компенсацией). В ТЗ это Фаза 2.
- **Увольнение** пилота/принципала (`fire`).
- **Смена мотора в межсезонье** (`engine`) — `SetTeamEngine` в репозитории есть, но сервис/хендлер отсутствуют.

### 8. `PrincipalTransfer` в вебе неполный
- CLI `change_principal` проверяет, свободен ли принципал или принадлежит другому игроку (с подтверждением).
- Web `PrincipalTransfer` (`service/service.go:313`) содержит `TODO - FIX we need to check is principal free` — не проверяет владельца и не запрашивает подтверждение.

### 9. Несогласованный знак бюджета в вебе (латентный баг)
- `PilotTransfer` списывает через `UpdateBudget(..., -price)` (минус = трата), а `UpdateBase`/`MakeUpdate` — через положительное значение. Драфт я специально построил на абсолютном `SetPlayerBudget`, чтобы это обойти, но `UpdateBudget` в игровых методах остаётся неоднозначным.

## Ожидаемо-различное (не баг)
- Драфт: CLI интерактивный ручной (`fillBotTeams`, `configureSeason`), веб — диспетчер + автозаполнение по рейтингу. Специфика веба.
- Подтверждения трансфера/принципала: CLI `y/n` в консоли, веб — через WebSocket. Специфика транспорта.
